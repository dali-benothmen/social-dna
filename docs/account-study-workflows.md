# Bounded account and research workflows

Implemented DX3-B foundation: a profile URL + plain-language goal over an **existing,
independently permitted library**, exact manifests, resumable local-media dispatch,
saved C1 bindings, cited reports and explicit follow-up. Native account acquisition,
paginated platform discovery and consented live checks remain open. This is not the
complete URL-only DX3 milestone; no scraper or new authorization integration ships.

```sh
socialdna workflow plan --mode account --url https://www.instagram.com/example/ \
  --goal 'Study the available account strategy' --max-posts 10
socialdna workflow run WORKFLOW_ID
socialdna workflow report WORKFLOW_ID --format markdown
socialdna workflow plan --mode research --url https://www.instagram.com/example/ \
  --goal 'What evidence supports the apparent hook pattern?' --max-posts 10
```

Use actual permitted data imported through the existing atomic account/C1 producers.
The host handles supported imports; users should not be asked to invent engine JSON.
Empty libraries return `account_observations_required` without network or fabricated
findings. Three recognized URL platforms do not equal three native collection adapters.
Historical aliases resolve from immutable account captures; ambiguous/reassigned aliases
require an explicit observed `--account-external-id`. This override is a declaration,
not independent platform verification.

Planning reads an immutable SQLite snapshot and pins exact current post revisions.
Dry-run never initializes storage. The sample is recent publication order, stable ID
tie-breaks, default 10/max 50; never ranked by outcomes. Known library count, selected
count and limit omissions do not prove complete inventory, deletion status or cadence.
Missing fields/private metrics remain unknown.

Optional `--analyze-media --permission-basis creator_owned_original` (or genuinely
`authorized_analysis`) pins hashes and dispatches real DX2 services, max twenty ordered
items/post and an account-wide byte budget. Remote references, position gaps, missing
bytes and incompatible URLs remain explicit. Each child checkpoint commits before work,
so interruption resumes the same child/run. Original media-source dependencies propagate
into child results; the coordinator cannot launder revoked source data into a fresh lane.
No downloading, models by default, implicit replacement or statistical fitting occurs.

Repeated `--context-revision REVISION` attaches actual same-account C1 profiles, reviews,
measured funnels, publishing evidence or platform records. They retain their distinct
types and citations: appearance is not conversion; guidance is not inferred ranking.
DX1 source-restricted API data cannot enter this generic analytical lane.

An explicit new plan with `--refresh-from PRIOR_WORKFLOW` pins current observations.
Reports distinguish new, changed content, unchanged/reobserved content and units removed
from the sample. Eligible unchanged media hashes/options reuse exact prior results.
Removed-from-sample does not establish deletion. Older reports stay frozen; a read-only
freshness hint never imports, refits or trains the host AI. Current freshness checks
detect selected-post corrections/unavailability and growth of known library inventory;
they are not a remote deletion monitor or automatic C1 refresh.

Research mode calls the actual R1 in-application draft writer with the question,
population and manifest citation. It invents no hypotheses or reviewed literature.
Prepared R7/R8 assessments can be explicitly inspected/reevaluated using existing
`research status`, `research history` and `research reevaluate` commands. A draft question
is not an evaluation-ready assessment; automated specialist preparation remains DX7.

Manifest/dispatch/study producers share 0019's existing composition projection,
ContentLocator, artifacts, recursive source eligibility and confirmed erasure. Eligible
citations can use existing memory projections; no indexing/model/new collection is
mandatory. External originals/exports/backups remain outside automatic deletion.

Access decisions remain conservative. TikTok's official
[Display API guide](https://developers.tiktok.com/doc/display-api-get-started) requires
approved products/scopes and authorization. YouTube's
[additional derived-metrics policy](https://developers.google.com/youtube/terms/derived-metrics-policy)
permits specified additional analytics subject to acceptance of its amendment; SocialDNA
does not assert that acceptance or widen DX1's native-only policy automatically.
Instagram's approved account-dependent integration remains a separate access gate.

Remaining acceptance: permitted URL-only identity/collection adapters, native page cursor,
quota and failure/deleted-item manifests, selective remote ingestion, substantive strategy
synthesis against compatible actual outcomes, and consented live source/host checks.
