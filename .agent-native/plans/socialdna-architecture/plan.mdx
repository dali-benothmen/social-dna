# SocialDNA Architecture and Implementation Roadmap

SocialDNA will be a Python 3.11+ CLI and library that turns authorized social-media media and account exports into synchronized observations, hypotheses, statistical associations, and experiments. The first release proves one complete local path before adding platform APIs: analyze a video, persist its timeline and evidence, stop the process, retrieve the knowledge in a later process, traverse its graph, and generate a cited report.

The architecture is approved. Milestone 0 is implemented; subsequent capabilities in this review document remain planned. Current implementation status is maintained in `PLAN.md` and `ARCHITECTURE.md`.

<Callout id="review-boundary" tone="decision">

**Approval boundary:** SQLite is canonical. Qdrant is a rebuildable semantic index. NetworkX is a bounded in-memory projection of graph rows stored in SQLite. No application code or dependency installation begins before review.

</Callout>

## A concrete first-release workflow

1. A user runs `socialdna analyze video ./clip.mp4 --depth standard --format json`.
2. SocialDNA initializes a local data directory, probes the media, detects scenes, samples/deduplicates frames, extracts audio, parses supplied subtitles, and computes deterministic features.
3. Optional local transcription/OCR/AI tasks run only when their models are installed and allowed. Missing tasks make the result partial, not fabricated.
4. SQLite commits the canonical timeline, observations, provenance, evidence, graph rows, vector documents, and a vector-index outbox operation.
5. Qdrant is updated idempotently after the SQLite commit. A failed update remains repairable from the outbox.
6. A later process runs `socialdna query`, hydrates semantic/lexical candidates from SQLite, expands a bounded evidence-bearing graph, and renders claims at their correct evidence level.

## Multimodal correlation workflow

- Extract measurable visual, audio, speech, text, publishing, and performance variables with analyzer/model provenance.
- Keep speech, supplied subtitles, and embedded OCR as distinct tracks; align all lanes to the original media timebase.
- Aggregate timeline features to declared post-level variables before performance statistics, avoiding false independence from frame-level rows.
- Compare metric snapshots at common post ages and within creator/platform/niche cohorts; preserve missing metrics.
- Let reasoning models propose taxonomy-bound hypotheses only from supplied evidence bundles.
- Retrieve supporting examples and counterexamples through SQL, FTS5, Qdrant, and bounded graph traversal.
- Use cluster-aware simple models, chronological/group validation, sensitivity checks, and false-discovery-rate correction.
- Persist the analysis specification, effect, interval, diagnostics, limitations, and counterexamples before saving an association.
- Require an experiment or defensible causal design before a finding can be marked causal.

## Principal risks

- **Local vector ceiling:** Qdrant Local uses an exclusive directory lock and warns beyond 20,000 points. Limit representations, cluster comments, warn early, and offer remote Qdrant post-v1.
- **Cross-store failure:** commit canonical vector documents and outbox rows in SQLite, then idempotently update Qdrant and reconcile.
- **Scientific overclaim:** enforce claim levels in schema, services, reports, tests, and the Agent Skill.
- **Platform access:** guarantee local/owned imports only; add official permission-aware adapters one by one after v1.
- **Heavy ML installs:** keep deterministic base behavior and put transcription/OCR/AI in explicit extras with model preparation and resource estimates.
- **Privacy:** require explicit provider configuration and remote-transfer consent; minimize audience identifiers and preserve permission provenance.

## Verification gate

The release-blocking smoke starts with an empty data directory, analyzes an authorized fixture, stores SQLite/artifact/vector/graph data, terminates the process, starts a second process, retrieves the video by semantics and FTS, traverses graph evidence, and renders JSON/Markdown reports whose substantial claims all resolve to stored evidence.
