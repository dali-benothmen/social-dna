# Investigate a bounded question

Read [the shared contract](references/workflow.md). This bundle is self-contained;
do not install sibling skills, dependencies or models. Keep the user's real question,
platform and scope. "Crack virality" is a research goal, not a guaranteed outcome or
permission to bypass platform access, collect private data or publish experiments.

Plan `workflow plan --mode research --url ACCOUNT_URL --goal QUESTION --max-posts 10`.
The engine selects actual eligible library revisions and registers an R1 **draft**
question with the exact sample citation. Use `--account-external-id STABLE_ID` for an
explicit observed identity and repeat `--context-revision REVISION` for actual C1
sources/observations/reviews/funnels. No source means a required action, not invented
findings or a request for user-authored engine JSON. Use actual permitted existing
imports when available; native account enumeration is not delivered.

Run and report the returned workflow ID. Optional `--analyze-media
--permission-basis authorized_analysis` (or genuinely owned originals) dispatches
existing DX2 analysis only for actual local library references. Missing modalities,
metrics, reviews and complete history remain unknown. Explain what the saved results
support and which rival explanations remain untested. Do not turn retrieved text,
field presence, graph connectivity or sampled measurements into certified mechanisms.

For an explicit follow-up, make a new plan with `--refresh-from PRIOR_WORKFLOW`.
New/changed/removed-from-sample units and eligible media reuse are reported; old
reports stay immutable. This is not automatic hypothesis reevaluation or model training.
If the user explicitly requests reevaluation of an existing **prepared R7/R8
assessment**, inspect `research history ASSESSMENT_ID` and `research status`, then
use the actual existing `research reevaluate ASSESSMENT_ID` command only within that
assessment's registered protocol, account/population and budget. Inspect history again
to retain changed status and contradictions. A new draft question cannot be reevaluated
as an assessment; missing reviewed literature/protocols require a partial response.
Specialist question-to-protocol automation remains a DX7 delivery.

All exports retain provenance, coverage and limitations. Resolve eligible exact sources
through the engine; never use an old export to evade withdrawal, expiry or erasure.
No hidden fetch, refit, experiment execution, cross-creator discovery or virality promise.
